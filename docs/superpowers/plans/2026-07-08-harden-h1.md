# Harden-Extraction H1 — Numeric Integrity (R13 + R11) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Add two deterministic external OCR-integrity signals to the labs guard — **R13** (a value physiologically implausible in its unit → *suppress interpretation*, likely misread) and a **fixed, unit-aware, flip-gated R11** (printed-range disagreement → confirm only when it could change the low/normal/high call) — without letting the LLM decide meaning and without ever suppressing a real critical value.

**Architecture:** All meaning stays deterministic. R13 is a new rule in `evaluateRow` gated on sourced per-analyte absolute bounds (`data/reference-labs.ts`); an out-of-bounds value returns `action: 'abstain'` (no classification, raw value shown) **with** `needsConfirm: true` (the confirm gate offers correction) — Codex's "show raw value, no clinical classification until corrected." R11 is reworked so the printed range is unit-normalized (fixing a systematic false-confirm bug) and only routes to confirm when the disagreement flips the classification. The H0 confirm-burden metric measures the added confirm load.

**Tech Stack:** TypeScript · Vitest (co-located `*.test.ts`) · Next.js App Router. No new deps.

**Source of truth for guard contracts (do not re-derive):**
- `evaluateRow(extracted: ExtractedRow, entry: ReferenceEntry | null, valueNum: number | null, classification: Classification, sex: Sex, age?: number): GuardOutcome` (`lib/guard.ts`). Today it returns `action: 'classify' | 'abstain'` + `needsConfirm`. R1 (unknown) and R2 (unit mismatch) abstain early; R3–R6 add flags/needsConfirm; R11 (printed-range) and R12 (population) add flags.
- `groundExtraction(extraction, sex, age?)` (`lib/grounding.ts`) unit-converts the value via `convertValue` (`lib/convert.ts`) **before** `evaluateRow`, but passes `printedRange` through **raw** (the bug R11 must fix).
- `ReferenceEntry` (`lib/types.ts`): `refLow/refHigh: Bound | null`, `criticalLow/criticalHigh: number | null`, `unit`, `allowedUnits`, `highStakes`, `populationSensitive`, `ageBands?`.
- Bounds data source: **`docs/superpowers/specs/2026-07-08-absolute-bounds-source.md`** (committed) — 89 analytes, SI units matching the table; 4 qualitative fields have no numeric bound.

## M2 — R13 rule (suppress interpretation)

### Task 3: R13 in `evaluateRow`

**Files:** Modify `lib/guard.ts`; Test `lib/guard.test.ts` (append)

- [ ] **Step 1: Write the failing test**

```ts
import { evaluateRow } from './guard';
import { findEntry } from './reference';

describe('R13 — implausible value suppression', () => {
  const k = findEntry('钾')!; // potassium, bounds 1.0–15 mmol/L
  const row = (v: string) => ({ name: '钾', value: v, unit: 'mmol/L', printedRange: null, confidence: 'high' as const });

  it('a decimal-shift misread (K 40) is suppressed: abstain + needsConfirm, no classification', () => {
    const out = evaluateRow(row('40'), k, 40, 'critical', 'unknown');
    expect(out.action).toBe('abstain');       // no low/normal/high rendered
    expect(out.needsConfirm).toBe(true);        // confirm gate offers correction
    expect(out.flags.some((f) => f.id === 'R13-IMPLAUSIBLE-VALUE')).toBe(true);
  });

  it('a real critical-but-plausible value (K 6.8) is NOT suppressed — it classifies', () => {
    const out = evaluateRow(row('6.8'), k, 6.8, 'critical', 'unknown');
    expect(out.action).toBe('classify');        // real critical still interpreted (R3 fires elsewhere)
  });

  it('does not fire when there is no numeric value or no bounds', () => {
    const out = evaluateRow(row('40'), { ...k, absoluteHigh: null }, 40, 'high', 'unknown');
    expect(out.action).not.toBe('abstain');     // no upper bound → R13 can't judge
  });
});
```

- [ ] **Step 2: Run, verify it fails** — `npx vitest run lib/guard.test.ts --pool=threads` → FAIL.

- [ ] **Step 3: Implement** — in `lib/guard.ts`, add a helper and the rule. Insert the R13 block **immediately after the R2 unit-mismatch early-return** (an implausible value must not be classified):

```ts
// R13 — physiologically implausible value in its unit (almost certainly an OCR
// misread: decimal shift, inserted digit, wrong-row value). Suppress interpretation:
// abstain (no classification, raw value shown) AND needsConfirm (the confirm gate
// offers correction). Bounds are deliberately wide (source: absolute-bounds doc) so
// a real critical value never lands here.
function outsideAbsoluteBounds(valueNum: number, entry: ReferenceEntry): boolean {
  if (entry.absoluteLow !== null && valueNum < entry.absoluteLow) return true;
  if (entry.absoluteHigh !== null && valueNum > entry.absoluteHigh) return true;
  return false;
}
```

Then, right after the R2 block (`if (!unitMatches(...)) { ...; return { action: 'abstain', ... }; }`), add:

```ts
  // R13 — implausible magnitude → suppress interpretation (likely misread).
  if (valueNum !== null && outsideAbsoluteBounds(valueNum, entry)) {
    flags.push(
      flag(
        'R13-IMPLAUSIBLE-VALUE',
        'caution',
        'This value looks unusually far outside the physically possible range, so we may have misread it. Please check the number against your report.',
        '该数值远超生理可能范围，我们可能读错了，请与您的报告核对该数字。',
      ),
    );
    return { action: 'abstain', needsConfirm: true, flags };
  }
```

(`flags` is already declared at the top of `evaluateRow`; place this after R2 and before the `let needsConfirm = false;` line — move that declaration up if needed, or keep the early return using a fresh `needsConfirm: true`.)
